# Анимированные виджеты «Радара AgPM» — инструкция по встройке

В прошлом комплекте виджеты жили внутри `*.dc.html` (среда прототипа, React). Здесь — **самодостаточный эталон без зависимостей**: `radar-widgets.html` открывается в любом браузере, код переносится копированием.

## Состав
- `radar-widgets.html` — 4 виджета: Сонар (период «День»), Доли (период «7 дней»), Кольцо 30 дней (период «30 дней»), логотип шапки. Каждый блок размечен комментариями с правилами.
- `favicon.svg` — статичная иконка сайта; `favicon-animated.svg` — SMIL-версия (анимируется в Firefox, в Chrome/Safari показывается статичный кадр — это норма).

## Как встроить (5 шагов)
1. **Keyframes — в глобальный CSS**, один раз на страницу: `rdSweep`, `rdBlip`, `rdArc1..3`, `rdLogoBlip` + правило `@media (prefers-reduced-motion: reduce){[data-anim]{animation:none!important;transition:none!important}}`. В CSS-modules/styled-components имена keyframes хэшируются — тогда либо выносите в глобальный слой, либо используйте `:global`/`createGlobalStyle`.
2. **Скопируйте `<svg>` виджета целиком** вместе с инлайн-стилями. У svg обязательно `display:block; overflow:visible`.
3. **Обёртка**: явная ширина (виджет тянется на 100% от неё). Для «Доли» и «Кольца» — `position:relative` (центр — абсолютный HTML-оверлей). Не зажимайте виджет контейнером с `overflow:hidden` впритык: блипы при вспышке растут в 1.65 раза, капы дуг выходят за габарит — оставляйте запас ≥6px или overflow:visible по всей цепочке.
4. **JS**: функции `buildSonar()` и `buildRing()` + массивы данных `SONAR_SETS`, `RING_DAYS` (вызывать после появления svg в DOM; в React — в `useEffect`). «Доли» и логотип — чистый CSS, JS не нужен.
5. Переключатель периода показывает ровно один виджет: День → Сонар, 7 дней → Доли, 30 дней → Кольцо.

## Почему «у нас не крутится / не там крутится» — частые ошибки
1. **Луч вращается вокруг угла svg** → потерян `transform-origin` в px (`120px 120px` для сонара, `14px 14px` для логотипа, `150px 150px` для подсветки кольца). Проценты и `center` для SVG-групп работают не во всех браузерах — только px координаты viewBox. Меняете viewBox — пересчитайте origin.
2. **Блипы не пульсируют или «улетают»** → у точки нет `transform-box:fill-box; transform-origin:center` (scale считается от угла svg).
3. **Вспышки не совпадают с лучом** → потерян отрицательный `animation-delay`. Формула: `delay = ((угол+90)%360)/360 * ПЕРИОД − ПЕРИОД`, где угол — в системе «0° = 3 часа, по часовой», а +90 — потому что луч стартует с «12 часов». Период луча и период блипов обязаны совпадать (8s у сонара, 4s у логотипа).
4. **Ничего не анимируется вообще** → keyframes не в глобальном CSS (см. шаг 1) либо в ОС включён reduced motion (это ожидаемое поведение, не баг).
5. **Дуги «Долей» начинаются с 3 часов** → потерян `transform="rotate(-90 120 120)"` на каждой дуге.
6. **Дуги другой длины после смены данных** → `stroke-dasharray="A B"`: A = доля × длина окружности (2πr: r46→289, r72→452, r98→616), B = остаток; и стартовый `stroke-dashoffset` в `rdArc1..3` должен равняться A.
7. **Подсветка кольца прыгает без плавности** → поворот делается через `element.style.transform` (JS), а `transition: transform .55s` висит на самом элементе; если задавать поворот SVG-атрибутом `transform`, transition не сработает.
8. **Обрезка по краям** (кап дуги, блип, подпись «1») → см. шаг 3: overflow:visible + запас.

## Замена мок-данных на бэкенд
- Сонар: одна точка = один материал дня; углы можно распределять детерминированно (хэш от id) — избегайте наложений ±8°.
- Доли: близкий/средний/дальний за последние 7 календарных дней; засечки — доли предыдущих 7 дней.
- Кольцо: `RING_DAYS` = последние 29–31 день, `[дальний, средний, близкий]` на день, последний элемент — сегодня; `RING_WEEKENDS` — индексы суббот/воскресений; масштаб столбика 2.2px на материал (при пиках >40 материалов уменьшайте коэффициент).
