# Несколько моделей до резервного уведомления

Основание: владелец поручил сделать сообщение о недоступности обзора крайним
случаем после нескольких попыток с разными моделями.

Генератор 7/30 дней использует одну политику: GPT-5.5 → MiniMax-M3 → GLM-5.2,
до двух попыток на каждой модели. Первый ответ, прошедший проверку русского
языка, полноты, неповторяемости и отличия от недельного обзора, принимается
без дальнейших вызовов. Между моделями передаются черновик и накопленные
замечания. Все модели получают одно окно; сокращение описаний и лимит argv
сохраняются. Невозможный для запуска размер запроса по-прежнему завершается
явным резервным результатом без фиктивных вызовов моделей.

Резервные провайдеры отличаются от основного. Оба прошли реальные короткие
проверки через OpenClaw, затем — проверки на всех 211 материалах за 30 дней:

- MiniMax-M3: отказ GPT имитирован, реальны только попытки MiniMax. Первый
  ответ отклонён из-за `ransomware`, `governance`, `survey`; второй исправил
  язык и принят. Итог: `attempts=4`, `provider=minimax`, `status=success`.
- GLM-5.2: отказы GPT и MiniMax имитированы, реальны только попытки GLM.
  Первый ответ отклонён из-за `headless`; второй принят. Итог: `attempts=6`,
  `provider=zai`, `status=success`.

Проверки не перепубликовывали сегодняшние тезисы. Артефакты сохранены в
`/tmp/radar-period-live-fallbacks/`, итоговые логи —
`/tmp/radar-period-live-{minimax,glm}.log`. Имитированные неудачи явно отделены
в логах от реальных обращений к провайдеру. Во всех реальных запросах
`materialCount=shownMaterialCount=211`.

Диагностика включает модель каждой попытки. В метаданные добавлен
`attemptModels`, а `provider` определяется принятой моделью. Для ошибок запуска,
тайм-аутов и отклонений сохраняются отдельные артефакты. Строка тайм-аута
не содержит команду с полным корпусом. Ошибка каждой попытки в общем сообщении
ограничена 600 символами, чтобы шесть ошибок помещались в контракт блока
метаданных; полные ошибки остаются в артефактах. Читательские блоки при полном
отказе по-прежнему задаёт `period_fallback_theses()`. Существующий отправитель
OpenClaw получает статус, принятую модель, число попыток и причину отказа
через неизменённую проекцию `_period_statuses()`.

## Бюджет времени

Ранее внешний тайм-аут сборки составлял 660 секунд и учитывал только дневной
анализ. Поэтому сборка могла оборвать модели периодов до завершения попыток.
Теперь он вычисляется из политик генераторов:

`3 × 180 + 2 × (3 модели × 2 попытки × 180) + 120 = 2820 секунд`.

Суточная задача `agpm_radar_v2_dual_run` профиля `projectmanager`, ID
`0af53bc1-2fea-4b66-bce6-b5d3a8e4f064`, до изменения имела предел 900 секунд.
Применено увеличение `timeoutSeconds` и предела ожидания вывода
`noOutputTimeoutSeconds` до 3600 секунд. Остальное содержимое задачи,
включая расписание, команду и настройки уведомлений, сохраняется. Исходный
JSON для проверки и отката: `/tmp/radar-period-chain/cron-before.json`.
`scripts/run_stage15_daily.sh` и модели Local Ru не меняются.

## Проверки

45 целевых тестов периодов и суточной границы прошли. Они проверяют принятие
на каждой из шести попыток, сохранение черновика при смене модели, фактический
провайдер, исчерпание всех моделей при пяти классах ошибок, ограниченную
диагностику, отсутствие технического текста у читателя и достаточный общий
тайм-аут сборки. Обязательные гейты:
`/tmp/radar-period-chain-{v2,kx,migrations}-verify.log`.

## Применено и проверено

Код: `b3e90de`. V2 verify завершился с exit 0 (335 passed, Ruff, mypy,
контракты, фронтенд и сборка). KX verify: exit 0, 603 passed / 204 expected
skips. KX verify_migrations: exit 0, все 807 тестов на временных локальных БД.

Через штатный `openclaw --profile projectmanager cron edit` применены оба
лимита 3600 секунд. Повторное чтение действующей конфигурации подтвердило:

- внутренний предел сборки — 2820 секунд;
- `payload.timeoutSeconds=3600`, `payload.noOutputTimeoutSeconds=3600`;
- расписание, argv, рабочая папка, окружение и настройки уведомлений идентичны
  исходным; задача остаётся включённой;
- argv указывает прямо на `/mnt/vdd/Radar/v2/scripts/run_stage15_daily.sh`,
  поэтому следующие запуски исполнят новый код из этого репозитория;
- обе переменные назначения уведомления OpenClaw присутствуют и сохранены.

Исходный и итоговый JSON, ответ CLI и его stderr сохранены в
`/tmp/radar-period-chain/`. Изменения приложения на сервере и перепубликация
уже восстановленного месячного обзора для этой политики не требуются.
