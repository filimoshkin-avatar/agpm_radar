# ADR-0022: редакторский пересмотр состава выпуска

Дата: 2026-09-19. Основание: запрос владельца включить подозрения на дубли в
ежедневный отчёт OpenClaw и дать возможность пересмотреть состав выпуска в `/po/`.

Гипотезы модели по-прежнему не меняют выпуск. После редакторской оценки владелец
может исключить выбранные карточки подтверждённых пар текущего выпуска,
просмотреть оставшийся состав и отдельно подтвердить публикацию. Карточки
прошлых выпусков и последняя карточка события защищены от такого исключения.
Оценки, хеш полного выпуска, версия отчёта, выбор карточек и аутентифицированный
редактор сохраняются сервером в закрытом журнале заявок. Сама оценка без
подтверждения остаётся локальным черновиком. Публичного API записи нет.

Сервис редактора хранит заявки в `/var/lib/radar-kx/issue-reviews` (0700/0600).
Существующий systemd-сервис получает StateDirectory, новые юниты и миграции БД
не нужны. POST требует JSON и отклоняет cross-site запросы. Статус публикации
может менять только служебный bearer, недоступный браузеру.

Контрольный хост раз в две минуты запускает `tools.process_issue_reviews` через
cron. Фиксированный SSH bridge читает очередь через loopback API редактора.
Публикатор повторно проверяет утверждённый хеш и материалы, пересобирает дневную
аналитику по новому составу, создаёт обычный correction candidate и использует
штатную транзакционную публикацию. Неудачная аналитика не заменяется старой
сводкой. После успеха запускается наблюдение для новой версии выпуска.

Повторы транспорта воспроизводят сохранённый пакет, включая восстановление
локального указателя после удалённой активации. Ещё не отправленный пакет можно
пересобрать при изменении базы; отправленные пакеты неизменяемы. Модельные
пересборки ограничены тремя попытками; владелец может повторно подтвердить
неудавшуюся заявку, если выпуск и отчёт остались прежними.

Ежедневный JSON получает `eventObservation`, текст уведомления — охват, число
подозрений, названия первых пяти пар и ссылку на дату в закрытом редакторе.
Ожидание, ошибка и частичная проверка явно отделены от отсутствия подозрений.
Поздний результат приходит дополнением по уже настроенному каналу OpenClaw;
квитанции предотвращают повторную отправку. Следующий daily подхватывает также
успешные отчёты, уведомление о которых не доставлено.
