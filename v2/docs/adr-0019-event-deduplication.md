# ADR-0019: событийная дедупликация выпусков

> Production-политика заменена режимом наблюдения: [ADR-0020](adr-0020-event-observation-calibration.md), 2026-09-19. Строгий алгоритм ниже остаётся экспериментальным.

Дата: 2026-09-19. Статус: код развёрнут с блокирующим контролем; сегодняшний
выпуск опубликован после явной редакторской проверки. Калибровка автономного
режима не выполнена. [Результаты релиза](event-dedup-release-2026-09-19.md).

## Решение

Идентичность документа и идентичность события разделены. Общая политика находится
в `packages/contracts/event_dedup.py`. Legacy-сборщик вызывает её через
`tools/event_pipeline.py`; V2 повторно проверяет состав при валидации кандидата,
сопоставлении с принятой БД и рендере из staging. Новых миграций нет.

1. До сетевых и модельных операций схлопываются одинаковые ID и URL. Удаляются
   UTM, известные tracking-параметры, ведущая локаль и AMP; содержательные query
   параметры сохраняются. Сохраняются альтернативные ссылки и происхождение
   обнаружения. Равный заголовок с равной датой — дополнительная точная проверка;
   почти равные заголовки паспортов используются для поиска подозрительных пар.
   Отсутствие обязательного паспорта блокирует новый кандидат.
2. Все отобранные материалы, включая ссылки AI Agents Directory, получают
   попытку загрузки текста. Из доступного текста извлекается паспорт: субъект,
   действие, объект, дата **события**, продукты, организации, тип, источник,
   дословное доказательство и проверяемые факты. Неизвестная дата остаётся `null`.
   Для недоступного текста используется явно непроверенный summary; такой
   материал не побеждает доступный проверенный источник.
3. Сущности, окно ±7 дней и текстовое пересечение находят кандидатов. Семантическое
   сходство само по себе не разрешает объединение. В первом варианте используется
   лексический поиск пар; эмбеддинги не требуются для корректности решений.
4. Точное совпадение субъекта, действия, объекта, продукта, типа и даты разрешает
   автоматическое объединение. Пограничные пары проходят LLM-арбитра со строгими
   полями `same_event`, `confidence`, `common_event`, `unique_facts_left`,
   `unique_facts_right`, `recommended_source`, `explanation`.
   Строковые boolean, NaN, лишние/повторные JSON-ключи и отсутствующие доказательства
   не принимаются. Совпадение всех пар внутри кластера обязательно: транзитивный
   мост A≈B≈C при A≠C останавливает выпуск.
5. Обзор раскладывается на события. После удаления покрытых событий публикуются
   только его уникальные сильные сигналы, с новым заголовком и резюме о них.
   Новый фокус повторно проходит редакционный фильтр релевантности.
   Если таких сигналов нет, обзор остаётся альтернативным источником.
6. Источник выбирается по доступности проверенного текста, затем первичности,
   подтверждённой дате события, числу фактов именно этого события и затем
   оригинальной журналистской публикации перед обзором. Причина выбора и все альтернативные ссылки
   сохраняются с кластером. Модельная рекомендация остаётся в аудите и не может
   поднять недоступную страницу выше проверенной публикации.
7. Реестр читает только принятые опубликованные выпуски за предыдущие 45 дней.
   `event_cluster_id` и `parent_event_cluster_id` сохраняются в существующей
   `material_evidence` с `kind=event_dedup`, привязкой к выпуску и материалу.
   Черновик, неудачная сборка и повторная сборка текущего дня реестр не продвигают.
   Новое действие по тому же продукту создаёт дочернее событие.
8. Сборщик проверяет уникальность карточек до рендера. Материал Directory
   выводится в специальном разделе один раз. Необъяснённый кластер, повтор ID,
   URL или события, пересечение fallback/обзора с проверенной карточкой и
   неразрешённая подозрительная пара блокируют публикацию.

## Доставка доказательств

`AgPM_daily_radar_DATE.event-audit.json` содержит решения пар, исключения и
нерешённые пары. `AgPM_daily_radar_DATE.events.json` связывает итоговые карточки
с SHA-256 Markdown и DOCX. Builder V2 проверяет эти файлы и соответствие URL и
заголовков Legacy-экспорта, затем переносит `eventDedup` в закрытый кандидат.
Внешний JSON API остаётся прежним; доказательства — часть редакционной БД.
Коррекции сохраняют принятые доказательства.

Для новых кандидатов и коррекций выпусков с 2026-09-19 паспорта обязательны.
Ранее опубликованные выпуски не переписываются автоматически. При запуске без
реестра история восстанавливается из принятых выпусков и кэша полных текстов;
результаты извлечения кэшируются по модели, версии prompt и содержимому входа.
Отсутствующая история не считается пустой историей. На один процесс допускаются
120 вызовов модели, запуск нового вызова прекращается после 900 секунд; каждый
вызов имеет timeout 120 секунд. Исчерпание бюджета останавливает выпуск, а
повторный запуск использует уже проверенный кэш.

Прогрев без публикации:

```sh
.venv/bin/python -m tools.event_pipeline \
  --source-db /path/to/accepted-release.sqlite \
  --issue-date 2026-09-20 \
  --cache /path/to/wiki/data/event-inference
```

## Калибровка и включение

Стартовые границы — 0.95 и 0.75; это **не результаты измеренной калибровки**.
Низкая уверенность оставляет пару раздельной. Средняя требует независимого
второго ответа; расхождение направляется на контроль. Высокое `same_event=true`
от модели разрешает автоматическое объединение только при структурном совпадении
и наличии проверенного `wiki/data/event-calibration.json`:

```json
{
  "policy_version": "events-v1",
  "prompt_version": "event-passports-v1",
  "arbiter_prompt_version": "event-arbiter-v2",
  "model": "openai/gpt-5.5",
  "high_confidence": 0.95,
  "medium_confidence": 0.75,
  "false_merges": 0,
  "evaluated_pairs": 80,
  "reviewed_by": "имя редактора",
  "dataset_sha256": "SHA-256 фактически размеченной выборки"
}
```

Пример нельзя устанавливать как готовую калибровку: число пар, ошибки, редактор
и хэш должны описывать реальную проверку. Выборка должна включать одно событие
в разных источниках, разные события одного продукта, обзоры и развитие старых
запусков. Без файла модельные совпадения остаются на контроле; точные структурные
совпадения работают. При смене модели, prompt или порогов старый файл отвергается.

Перед выкатом: прогреть 45 дней истории, проверить реальный состав выпусков,
установить совместимые candidate schema / publisher / activator, затем обновить
Legacy runtime mirror и проверить новую сборку. Для повторной обработки уже
вышедшего выпуска 2026-09-19 сначала нужен новый проверенный manifest либо
редакционная коррекция с паспортами; существующий выпуск здесь не изменён.

Регрессии в `tests/test_event_dedup.py` используют синтетические паспорта сценария
Anthropic/финансовые консультанты и проверяют алгоритм, а не подтверждают саму
новость. Проверяются также Stonly в двух разделах, сохранение доказательств через
реальный package/replay, граница 45 дней и прогрев холодного реестра.

## Исходная проверка в рабочем дереве

- V2 `scripts/verify.sh`: PASS, 381 тест, Ruff, strict mypy, контракты,
  frontend smoke, изоляция и сборка production artifact.
- KX `scripts/verify.sh`: PASS, 603 passed / 204 ожидаемых skipped.
- KX `scripts/verify_migrations.sh`: PASS, полный прогон на временных локальных БД.
- 36 новых регрессий событийной дедупликации: PASS.
- Все 105 опубликованных выпусков принятой локальной БД проходят новый валидатор.
  Старый выпуск 2026-06-19 содержит одинаковые заголовки; новый контроль не делает
  такой архив недоступным. Повторная публикация нового выпуска с такими заголовками
  блокируется.

Логи: `/tmp/radar-event-v2-verify.log`, `/tmp/radar-event-kx-verify.log`,
`/tmp/radar-event-migrations-verify.log`, `/tmp/radar-event-existing-issues.json`.
Реальные модельные вызовы, калибровка, изменение опубликованных документов и
производственное развёртывание в эту проверку не входили.

Последующий прогон на реальном выпуске 2026-09-19 обнаружил ошибку разделения
событий по разным action без подтверждённых дат и слишком широкий запрет
арбитру объединять возможности исходного запуска. Исправления и фактический
отказ автоматической сборки до редакционного контроля описаны в
[отчёте проверки](event-dedup-check-2026-09-19.md). Реальная приёмка автоматического
объединения этим прогоном не достигнута.
