# ADR-0021: отчёты о повторах доступны только продакт-оунеру

Дата: 2026-09-19. Статус: принято по прямому уточнению владельца.
Меняет аудиторию отчётов ADR-0020. Публичное размещение было ошибкой реализации.

Единственная пользовательская точка входа — существующий закрытый раздел
`https://radar.agpm.space/po/`, вкладка «Повторы выпусков»
(`/po/#event-observations`). Действующая авторизация проверяется Caddy и самим
KX EditorService. Подписка на раздел «Агент» не даёт этих прав.

Публичный фронтенд не содержит панели, логики загрузки или ссылок на отчёты.
Старый `/api/event-observations/*` закрыт Caddy и удалён из V2 dispatcher/OpenAPI.
Простой переход по URL не предоставляет доступа.

После авторизации PO-сервис читает отчёт через loopback V2 endpoint
`/api/owner/event-observations[/YYYY-MM-DD]`. V2 повторно проверяет длинный
серверный bearer-токен в constant time. Токен не передаётся браузеру и не попадает
в JSON/логи. Внешний маршрут `/api/owner/*` также закрыт Caddy. Отсутствующий,
короткий или неверно защищённый файл ключа означает отказ, а не публичный доступ.

V2 использует `/etc/radar-v2/owner-observations.token`, mode 0400, owner radar-v2-api;
путь передаётся через `RADAR_V2_OWNER_OBSERVATIONS_TOKEN_FILE` в `api.env`.
Это копия действующего bearer-токена редактора. При ротации editor token необходимо
обновить эту копию. V2 перечитывает файл на каждом запросе; редактор перезапускается
по обычной процедуре. Пароль пользователя и остальные ключи доступа не меняются.

Генерация отчётов, версии и хеши, фоновое продолжение, техническая уникальность и
неблокирующая политика остаются прежними. Новых systemd-юнитов и миграций нет.
Разметка сохраняется в браузере и экспортируется для отдельного операторского
импорта; серверные редакторские решения не имитируются.

Проверки включают анонимный отказ по обоим старым/новым URL, отказ при неверном
токене и правах файла, вход в PO, просмотр сегодняшнего отчёта, экспорт оценок,
отсутствие панели/запросов отчёта в публичном выпуске и неизменность его карточек.
