# Внутренний поиск KX и отчёт покрытия

Дата: 2026-08-22. Срез 1.4 плана `docs/radar-v2-kb-engineering-plan-2026-08-22.md`.

Статус: реализовано и проверено. Гейт по дымовым запросам подтверждён на production read-only.
Новых зависимостей нет — поиск работает на индексах `search_ru` и `search_en`, которые уже
существуют в схеме с миграции 001.

---

## 1. Команды

```bash
radar_kx search "агентное управление проектами" --scope current --limit 10
radar_kx search "artificial intelligence governance" --scope canon
radar_kx coverage-report        # ненулевой код возврата, если гейт не сошёлся
```

---

## 2. Что делает поиск

**RRF по двум языкам.** Один и тот же запрос разбирается `websearch_to_tsquery` дважды — русской и
английской конфигурацией, — ранжируется `ts_rank_cd` по каждой, и два ранжирования сливаются
reciprocal rank fusion: `score = Σ 1/(60 + позиция)`. Константа 60 — из исходной работы по RRF и
общепринятая по умолчанию; она достаточно уплощает голову каждого списка, чтобы один уверенный
список не подавил другой.

Каждый результат сообщает `ruPosition` и `enPosition` — в каком из двух ранжирований он найден.
Пусто в одном из них означает «этот индекс его не вернул», и это видно, а не скрыто в одном балле.

**Почему не эмбеддинги.** pgvector — решение по измеренной необходимости после вертикального среза
(§13.3, срез 2.16), а не до него. Лексический поиск сначала должен провалить замер; сейчас замера
нет.

### 2.1. Снипеты с проверенными offsets

Это главное требование среза. Каждый результат несёт `charStart` и `charEnd` — диапазон снипета
внутри `document_versions.canonical_text`, — и диапазон **проверяется по хранимому тексту до
возврата**: перед выдачей выполняется один запрос, который извлекает `substr(canonical_text, ...)`
для всех попаданий и сравнивает с текстом снипета. Несовпадение — исключение, а не тихая выдача.

`ts_headline` обычно возвращает непрерывный кусок исходного текста, но не обязан: он схлопывает
пробелы и может выбросить фрагмент. Поэтому headline, который не находится в чанке дословно,
**отбрасывается** в пользу начала чанка — грубее, но offsets честные. Флаг
`snippetIsMatchCentred: false` в результате говорит, что это произошло.

Смысл строгости: триггер `validate_exact_claim_evidence` принимает доказательство только при точном
совпадении подстроки и SHA-256 цитаты. Поиск, выдающий приблизительные offsets, породил бы поток
отказов на уровне БД, и разбирать их пришлось бы позже и дороже.

### 2.2. Scope — это класс членства, и он называется явно

Четыре области, четыре разных знаменателя (corpus-membership contract §9):

| `--scope` | Что это | Документов на 2026-08-22 |
|---|---|---:|
| `current` | последний снимок периметра — что отобрал активный content release | 275 |
| `historical` | union всех снимков периметра | 275 (расхождение с `current` латентно, D3) |
| `canon` | канон AgPM и стандарты, `source_kind = 'canon_import'` | 32 после загрузки 1.6 |
| `corpus` | весь корпус, включая 8 038 неотобранных документов | 8 313 |

Значение по умолчанию — `current`. Умолчание «всё» смешало бы классы молча; неизвестное имя scope
отвергается, а не расширяется до корпуса.

## 3. Отчёт покрытия

`coverage-report` печатает по каждому классу: документов, документов с complete-версией, версий,
чанков, символов и долю полноты. **Классы не суммируются.** Покрытие по периметру выпусков,
по всему корпусу и по канону — три разных вопроса, и один процент по их объединению не значит
ничего.

### 3.1. Гейт

| Проверка | Условие |
|---|---|
| `perimeterFullTextComplete` | все документы текущего периметра имеют complete-версию **и** периметр не пуст |
| `smokeQueriesMeetTheirFloor` | `искусственный интеллект` ≥ **993** чанков, `artificial intelligence` ≥ **633** |

Пороги — замер 2026-08-21 из `docs/radar-kx-production-fulltext-2026-08-21.md`. Корпус растёт,
поэтому точные числа невоспроизводимы, и гейт сформулирован как «не менее». Падение ниже означает,
что сломался индекс, языковая конфигурация или сам корпус.

Пустой периметр **не проходит** проверку полноты. Без явного условия `> 0` пустое хранилище давало
бы зелёный гейт: `0 == 0`.

### 3.2. Подтверждение на production

Read-only, внутри `BEGIN READ ONLY`, 2026-08-22:

```
ru | 995
en | 651
```

Оба порога соблюдены, оба числа немного выросли с 21 августа — ровно то поведение, ради которого
гейт сформулирован как нижняя граница, а не как равенство.

Сам `coverage-report` на production **не запускался**: он требует `SCHEMA_VERSION = 3`, а
production пока на схеме 2. Дымовые запросы выполнены обычным SQL, читающим те же данные.

## 4. Как проверено

`kx/scripts/verify_migrations.sh` поднимает временную базу и прогоняет 12 тестов поиска в дополнение
к остальным. Проверено:

- headline, найденный дословно, центрирует снипет; ненайденный — деградирует к началу чанка, и в
  обоих случаях `text[start:end] == snippet`;
- каждый снипет реального результата воспроизводится из своих offsets по `canonical_text` в БД;
- **негативный тест**: искусственно сдвинутый на 7 символов offset ловится и роняет запрос —
  проверка не декоративна;
- арифметика RRF: балл каждого попадания равен сумме `1/(60 + позиция)` по присутствующим
  ранжированиям, результаты отсортированы по баллу, и попадание из обоих списков обгоняет попадание
  из одного;
- scope разделяет классы: поиск по `canon` возвращает только канон, по `current` на пустом периметре
  — пустой результат, а не молчаливый откат к корпусу;
- неизвестный scope отвергается;
- пустой периметр не проходит гейт полноты;
- дымовые пороги 993 и 633 сообщаются вместе с фактическими числами, против которых их судят.

Сквозной прогон на загруженном каноне (32 документа, 517 чанков) возвращает осмысленные результаты
с корректными offsets — например, запрос «агентное управление проектами» находит Манифест v3 и
страницу ценностей.

## 5. Чего срез не делает

- Не строит публичный поиск: `/api/search` Radar V2 к этому отношения не имеет и не смешивается
  с ним (§16).
- Не измеряет Recall@10, MRR и p95 latency: это вертикальный срез 2.1 на gold-наборах, и планку по
  ним ставит владелец **после** замера и **до** масштабирования (P29).
- Не вводит pgvector.
- Не запускает `coverage-report` на production — нужна миграция 003.
- Не разделяет права доступа: это внутренний инструмент, а не endpoint. Разделение public и
  research идёт срезами 3.2 и 2.14.
