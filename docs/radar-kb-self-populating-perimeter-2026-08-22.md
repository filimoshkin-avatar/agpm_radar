# Срез 2.2: самопополняемый периметр

Дата: 2026-08-22. Состояние: **работает, таймер включён**.

## 1. Опрос, а не хук

KX спрашивает у Radar V2 активный content release **по таймеру**. V2 не изменён, хука не имеет и не
знает, что KX существует.

Это не эстетика. Путь публикации, который обязан вызвать базу знаний, делает базу знаний способной
сломать публикацию. ADR-0005 §18: связь односторонняя и только на чтение — V2 экспортирует свой
периметр, KX его импортирует.

Оба сервиса живут на Local Ru, поэтому пересылать нечего.

## 2. Проверки «изменилось ли» нет

`source_sha256` — это хеш файла release-базы. Повторный экспорт неизменившегося релиза даёт
идентичный артефакт, и `import_issue_perimeter` его узнаёт: `perimeter_source_id` уже есть,
`source_sha256` совпадает, ничего не пишется.

Поэтому опрос экспортирует каждый раз и оставляет решение импорту. Нет отдельной логики сравнения,
которую можно было бы написать неправильно.

Если тот же `releaseId` вдруг придёт с другим содержимым, импорт **откажет** с ошибкой, а не тихо
перезапишет снимок. Неизменяемый снимок, который меняется, — это не снимок.

## 3. Один привилегированный шаг, и только один

`/var/lib/radar-v2/content` закрыт для всех, кроме пользователя API V2 (`drwxr-x--- root:radar-v2-api`,
`active.json` — `0600`). Менять это не дело этого проекта.

Поэтому экспорт запускается как `ExecStartPre=+` (то есть от root) и кладёт артефакт в
`StateDirectory` юнита, откуда его читает `radar_kx`. Всё, что после, — непривилегированный
пользователь. Сам экспорт открывает sqlite с `immutable=1` и использует только стандартную
библиотеку, поэтому он не может писать в работающий API, блокировать его или мешать ему.

У юнита нет интернета вовсе: `IPAddressDeny=any` плюс localhost.

## 4. Первый прогон

```
экспорт:  49 выпусков, 277 строк, 277 материалов
импорт:   275 документов, 0 новых, 0 поставлено в очередь
```

Ноль новых — верный ответ: этот релиз уже был импортирован в срезе 1.1. Второй запуск подряд — чистый
no-op.

Таймер: `OnBootSec=5min`, `OnUnitInactiveSec=30min`, `Persistent=true`. Полчаса — не про задержку
(V2 публикуется несколько раз в день), а про то, чтобы периметр не устаревал больше чем на один
опрос без чьей-либо памяти.

## 5. Две ошибки по дороге, обе записаны в юните

1. `ReadWritePaths` называет путь, который mount-namespace должен уже найти, а привилегированный шаг,
   который должен был его создать, работает **внутри** этого namespace. Юнит падал на шаге NAMESPACE,
   ничего не сделав. `StateDirectory` создаётся systemd до этого — для того он и есть.
2. `import-perimeter` принимает путь позиционно, а не `--path`.

## 6. Встраивание в существующий контур

Контур `runs/` → `wiki/daily/` → `wiki/monthly/` → основная wiki продолжает работать как работал.
Этот срез к нему **присоединяется**, а не подменяет его (§6А.2 плана): он берёт то, что V2 уже
опубликовал, и доводит до `fetch_queue`. Ничего не пишется в `knowledge/`.
