# Radar V2 Knowledge Base: точка входа для реализации

Дата: 2026-08-22. Состояние: **фаза 1 выполнена целиком, в production ничего не применялось.**

Этот файл — стартовая страница для новой сессии. Читать первым, затем план.

## 1. Что делаем

Публичная база знаний Radar V2 на основе материалов выпусков: wiki, навигация, граф, рейтинги и
диалоговый агент, где каждое фактическое утверждение подкреплено точной цитатой из источника.
Пополняется автоматически после каждого выпуска.

**Канонический план — единственный:**

```
docs/radar-v2-kb-engineering-plan-2026-08-22.md      (редакция 5.4, 1313 строк)
```

Параллельных roadmap нет. `docs/radar-v2-knowledge-base-roadmap-2026-08-22.md` — историческая
запись направления, как план отменён.

**Как читать план:** §1 — 37 решений владельца, все развилки закрыты. §2 — отменённые формулировки,
чтобы они не всплыли из старых цитат. §13 — фазы. §16 — чего не делать. Остальное по ссылкам.

**Важно:** план местами расходится с тем, что реально на диске. Расхождения найдены фазой 1 и
перечислены в §3 ниже. Читая план, сверяйтесь с ними.

## 4. Что требует решения владельца

1. **Применять ли миграцию 003 к production.** Написана, проверена на двух базах, SQL-тесты

3. **Утвердить ADR-0004…0008.** Это единственное, что фаза 1 просит у владельца по плану.
4. **Знаменатель разметки:** 275 документов для разметки и оценки, 277 строк отбора для
   редакционных метрик, `material_scores` ключуются документом (contract §8). Подтвердить.
5. **Четыре документа из веб-архива** без URL и даты снимка блокируются для публичных цитат до
   среза 2.3. Принять как временное ограничение?

## 5. С чего начинать дальше

Фаза 1 закрыта. Дальше — фаза 2, её вход — **срез 2.0** (профиль Hermes и оркестратор), затем
**2.1** (вертикальный срез на 20-30 документах).

Но **2.0 и 2.1 упираются в применение миграции 003**: без схемы 3 нет ни провенанса, ни
`egress_audit`, а без `egress_audit` невыполним контракт egress из ADR-0005. Пока миграция не
применена, доступны работы, не требующие записи в KX:

| Что можно делать без миграции | Почему |
|---|---|
| Определение gold-наборов для 2.1 (вопросы, ожидаемые span'ы) | это файлы, не записи в БД |
| Выборка 20-30 документов вертикального среза | read-only по периметру |
| Разбор 34 страниц wiki, которые парсятся механически (2.5, первая половина) | реестр уже построен срезом 1.5 |
| Подготовка отчёта расхождений разметки (2.13) | read-only |
| Проектирование профиля Hermes по образцу NRD | конфигурация, не применение |

Определения срезов 2.x расписаны в §13.3 плана.

- применение миграции к production и переключение `/opt/radar-kx/current`;

- расширение списка моделей на Local Ru за пределы `zai/glm-5.2` и `minimax/MiniMax-M3`.

## 7. Факты, которые дорого выяснять заново

**Хосты.** Control-хост — здесь, 4 vCPU / ~5 GB RAM. Local Ru — `root@147.45.99.225`, ключ
`/root/.ssh/local_ru_admin`, 4 vCPU / 7 936 MB RAM / swap 8 GB / 50 GB свободно.

**KX** (замер 2026-08-22): 8 313 документов, 6 792 версии (6 489 complete), 19 010 чанков, БД
688 MB, очередь 5 933 succeeded / 2 378 failed. Схема **2**, дрейф D1 присутствует. Периметр
текущего релиза `rel_473de6c600563860305e2bd0`: 77 выпусков, 277 строк отбора, 275 документов,
полный текст 275/275. Дымовые запросы FTS на 2026-08-22: ru 995, en 651 (пороги 993 и 633).

**Локальная разработка.** На control-хосте установлен `postgresql-16-pgvector` и создана роль `root`
с SUPERUSER — это нужно `verify_migrations.sh`, который поднимает временные базы `radar_kx_test_*`
и удаляет их за собой. Production это не затрагивает.

**Существующая wiki** — не изобретать заново:
`/root/.openclaw-projectmanager/workspace/knowledge/agpm/` (93 файла, 63 авторских страницы;
`SCHEMA.md` задаёт словарь связей и конвенции) и `.../knowledge/agpm-radar/` (204 файла). Не под git.
Реестр строится командой `kx/scripts/wiki_inventory.py`.

**Модели.** Hermes 0.20.0 на Local Ru, `127.0.0.1:8642`, `zai/glm-5.2` и `minimax/MiniMax-M3` —
облачные API, локального вывода нет. Образец изоляции профилей — юниты NRD на том же хосте.

**Три находки NRD переиспользовать, а не изобретать:** собственный runtime; патч allowlist моделей;
root-owned env 0600 с ключами на профиль. Записаны в ADR-0005 §3.

**Известные дефекты** — §5 плана, D1-D13. Закрыты кодом или зафиксированы: D1 — миграцией 003
(не применена); D9 и D12 — таблицей `version_provenance` и коррекциями; D3 — правилом обращения
в contract §6; остальные открыты.

## 8. Перед первым коммитом

Три гейта: `kx/scripts/verify.sh`, `kx/scripts/verify_migrations.sh` (нужен локальный PostgreSQL),
`v2/scripts/verify.sh`.

Если `uv export` выдаёт цветной вывод и `verify.sh` падает на сверке lock-файла — запускать с
`NO_COLOR=1`. Это особенность окружения, а не расхождение lock'а.
