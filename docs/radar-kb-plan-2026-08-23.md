# План реализации базы знаний, редакция после решений владельца

2026-08-23. Заменяет очередность §6 документа юзкейсов. Основание: пятнадцать решений
владельца (`radar-kb-topic-skeleton-2026-08-23.md` §14), применённая миграция 022 и
замеры достижимости (`radar-kb-usecase-feasibility-2026-08-23.md`).

## Почему очередность меняется

Первая очередь §6 — «доказательный поиск по единому корпусу» — неисполнима в том
виде, как написана, по трём измеренным причинам:

1. **Поиск без полей миграции 022 будет искать по нелейбленной куче.** Фильтр
   «знание или хроника рынка» (решение 3), вид доказательства (решение 7) и статус
   (решение 6) стоят на `claim_reading` и `claim_topics`, а те пусты.
2. **8,6 % цитат порваны границей.** Публиковать поиск по базе, где каждая
   двенадцатая цитата начинается со строчной буквы посреди фразы, — подрывать
   доверие к атому продукта до его запуска.
3. **«Единый корпус» противоречит действующему решению публиковать только из
   опубликованного среза.** Это не инженерный вопрос, а продуктовый — он в списке
   вопросов ниже.

## Этапы

### Этап 0а. Границы цитат и даты — код, ноль обращений к модели

Расширение спана до границы предложения по сохранённому полному тексту, влево и
вправо, потолок — абзац. Заголовки и пункты списков, у которых терминатора нет в
самом источнике, остаются как есть с пометкой «источник так устроен». Пересчёт
эмбеддингов исправленных цитат — минуты.

**Почему это не переизвлечение.** Проверено: на `claim_evidence` стоит только триггер
проверки спана (`BEFORE INSERT OR UPDATE`), запрета изменений нет. Значит границы
правятся на месте, `claim_id` сохраняется, а триггер заново доказывает, что
расширенная цитата дословна. Ничего не осиротеет.

Сюда же — разбор даты публикации. **Поправка к оценке:** дат в ISO по всему хранилищу
7 875 из 7 986, но **внутри периметра разбираемая дата есть только у ~185 материалов
из 1 102**. Значит Обсерватория как датированная хроника опирается на дату публикации
там, где она есть, и на дату обнаружения радаром в остальных случаях — с явной
пометкой, какая из двух показана.

| | |
|---|---|
| Стоит | 0 модельных вызовов, 0 часов владельца, дни |
| Разблокирует | доверие к цитате — атому всего продукта |
| Раньше нельзя | ничего, это первый шаг |

### Этап 0б. Прочтение 7 929 утверждений — машина, без визы

Один проход заполняет четыре решения сразу: вид материала (7), первоисточник и
признак пересказа (1), допуск знание / Обсерватория / отсев (3), срок по правилу (11).
Плюс `claim_topics` — тема на утверждении, плюс статусы рождения по правилу.
Отклонённое пишется в журнал, а не исчезает.

| | |
|---|---|
| Стоит | ~700 пакетных вызовов, ~1,5 часа, 0 часов владельца (по желанию 30 минут на выборку отклонённого) |
| Разблокирует | фильтры UC-01, карточку понятия UC-04, карту пробелов UC-10, Обсерваторию, статусные лейблы |
| Раньше нельзя | до 0а прочтение классифицирует и **отсеивает** по оборванным цитатам — это молчаливая потеря содержания |

### Этап 1. Поиск и research-агент — первая очередь §6, но для своих

Смысловой поиск по всему корпусу: один локальный прогон эмбеддера по 15 603
фрагментам, порядка трёх часов на процессоре, без обращений наружу. Полнотекстовый по
корпусу уже работает — это не новый слой. Гибрид с фильтрами тема / статус / вид /
допуск. Агент со структурой ответа из §5 и цепочкой раскрытия UC-02. Здесь же
меряется прямая половина критерия §7.

| | |
|---|---|
| Стоит | модельные вызовы только на ответы; **~1 час владельца** на приёмку формата ответа |
| Разблокирует | UC-01 и UC-02 в исследовательском режиме |
| Раньше нельзя | агент без прочтения не может сказать, **чем** подкреплено, и не отличает знание от хроники |

### Этап 2. Связи и карточки понятий

`knowledge_links` четырёх типов конвейером «шорт-лист обоими методами → судья →
без визы»: ~2 тыс. вызовов. Карточки 229 понятий строятся **из `claim_topics`, а не из
графа** — ни тем, ни сущностей в графе нет. Карта пробелов. Очереди повышения статуса
и пересмотра по сроку в интерфейсе владельца.

| | |
|---|---|
| Стоит | ~2 тыс. вызовов; часы владельца — только очередь повышения, темп задаёт она |
| Разблокирует | UC-04, UC-10, обратную половину критерия §7, два достижимых режима графа |
| Раньше нельзя | связывание до 0а и 0б повторит измеренные «половина мимо предмета» и будет судить по обрывкам |

### Этап 3. Публичный запуск

Обсерватория, публичный поиск и агент по опубликованному срезу, лейблы статуса, вида
и пересказа наружу, лицензия и подпись.

| | |
|---|---|
| Стоит | недели на интерфейс; 2–3 часа владельца |
| Раньше нельзя | публиковать без статусных лейблов — нарушение её §2.2 по построению; выпускать агента без замеренного §7 — кризис доверия на первой же ошибке |

### Этап 4. Wiki-синтез и аналитика по мере данных

UC-09 (предложения в очередь владельца), UC-12 (черновик машины под её визой), UC-03
подмножеством (3 591 утверждение с цифрой), UC-05 сущностный слой (самый дорогой во
всём списке: сущностей ноль), UC-07 — накоплением, UC-13 — после подсчёта кейсов.

## Минимальный состав первого публичного запуска

- поиск по опубликованному срезу с фильтрами тема / вид / статус;
- агент по срезу: структура §5, пометка «машинный ответ», цитаты под ответом, без
  постоянных адресов у ответов;
- Обсерватория: датированная хроника сигналов с первоисточниками;
- карточки 229 понятий: цитаты, статусы, четыре типа связей;
- wiki: 63 страницы как есть, навигация по жанрам разделов;
- на каждой единице лейбл: статус знания, вид материала, «пересказ → первоисточник»;
- лицензия с атрибуцией, формат цитирования, пометка машинного текста.

**За бортом запуска:** сущностный граф, подписки, UC-03, UC-07, UC-12, UC-13, десять
оценок.

## Что остаётся известным ограничением

Второй дефект цитат — следы разбора PDF: 726 цитат с переводом строки, 443 со
склеенными словами, 36 с переносами. Кодом расширения спанов это не чинится, только
перепарсингом, а перепарсинг родит новые версии и новые идентификаторы утверждений.
**Не чиним сейчас.** Записываем как измеренный предел качества и возвращаемся, когда
появится браузерный рендеринг — необходимость которого уже измерена отдельно
(80 документов).

## Пять решений владельца по этому плану (2026-08-23)

| № | Вопрос | Решение |
|---|---|---|
| 1 | Состав первого публичного запуска | **как в плане, с агентом**: поиск по срезу, диалоговый агент, Обсерватория, карточки 229 понятий, wiki как есть |
| 2 | Охват поиска и агента | **правило, а не число**: знание формируется из материалов, вошедших в выпуски радара, **плюс методический корпус AgPM**. Набор растёт с каждым выпуском |
| 3 | Подпись | **двойная**: авторские страницы — именем владельца как автора методики; карточки, синтезы и ответы — «AgPM Radar, машинная сборка»; атрибуция по лицензии на адрес базы |
| 4 | Обсерватория | **срез по классам событий**, а не лента: покажи все инциденты / стандарты / релизы за период. Вид материала проставляется прочтением |
| 5 | Оценки идей | **четыре оси, машина, с пометкой**, без сводного балла. Остальные шесть — после замера стоимости оценивания |

Решение 2 поправило мою формулировку: я держал канон отдельно, как справочный слой,
а он **входит в область базы**. В коде это существующие периметры `historical` и
`canon`; корпус вне выпусков остаётся за границей.

Решение 4 закрыло дыру в документе юзкейсов: у Обсерватории появилась читательская
задача, и она сходится с тем, что уже есть в данных — вид материала будет проставлен
прочтением на этапе 0б, а значит срез по классам собирается без отдельного слоя.

Решение 5 снимает арифметику 163 часов с этого юзкейса: четыре оси считает машина,
каждая помечена как машинная, сводного балла нет.
