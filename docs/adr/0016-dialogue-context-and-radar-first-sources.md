# ADR-0016: Контекст диалога и статьи Радара по умолчанию

Дата: 2026-09-12. Статус: принято по запросу владельца.

## Решение владельца

Диалог учитывает контекст. Поиск прежде всего в статьях, попавших в Радар.
Канон подключается только по явному запросу пользователя, например:
«найди все упоминания в статьях Радара и канонических документах» или
«поиск во всех документах базы знаний».

## Реализация

- Клиент передаёт последние пары вопрос/ответ; сервер принимает до шести пар,
  3600 символов суммарно. История — недоверенный контекст, не доказательства.
  Предыдущие ответы помогают разрешать местоимения и сравнения, но факты нового
  ответа должны подтверждаться вновь найденными цитатами.
- При наличии истории выполняется ограниченный запрос к разрешённой модели,
  превращающий уточнение в самостоятельный поисковый вопрос. Ошибка этого шага
  оставляет детерминированный поиск с последней репликой и исходную историю для ответа.
- Область `radar` требует существования пути утверждения к выпуску через
  `agent.statement_trail`. Это все исторические снимки состава выпусков,
  включая статьи, которые впоследствии могли снять редакционной коррекцией.
- `radar_canon` явно объединяет статьи с импортированным каноном;
  `canon` означает явное «только канон»; `all` — явный запрос всей базы.
  Импорт канона использует зарезервированные адреса `agpm-canon:/`.
  Любая область остаётся внутри допущенного представления `agent.statement`:
  отвергнутые/непрочитанные данные не открываются.
- В объединённой области первые места отдаются статьям (до пяти из восьми),
  остальные — дополнительно запрошенным источникам. Обычный `/search` использует
  тот же разбор явного выбора. Отсутствие результатов не расширяет область.
- Явный выбор сохраняется в продолжении диалога, пока пользователь его не сузит
  либо не начнёт новый диалог. Клиент переносит исходную пользовательскую фразу
  отдельно от ограниченной истории. Сервер выводит область из этой фразы, а не
  из произвольного значения `sourceScope` или предложения модели.
  На момент реализации это объявленное рабочее предположение к дополнительному
  вопросу владельцу о продолжениях; отдельного подтверждения не получено.
- Автоматические карточки, запросы которых не поддерживают область источников,
  добавляются только при явном `all`. Граф, wiki и прочие самостоятельные вкладки
  сохраняют собственное назначение; их ручное открытие не расширяет поиск ответа.
- Ответ показывает выбранную область. SSE и запасной JSON-маршрут передают одну
  историю и одну фразу выбора. Начало нового диалога сбрасывает обе.

## Кэш без миграции

ADR-0012 фиксировал смешивание admission: `scope` в схеме допускает только
`public/research/editor`. Менять этот CHECK или подставлять фиктивный release_id
не требуется. `question` остаётся исходным вопросом для журнала, а
`normalized_question` получает суффикс с хэшем контекста: версия диалога, история,
admission, область документов, состояние синхронизации и пятиминутный интервал.

Чтение и запись используют одну функцию формирования ключа. Старые строки не
изменяются, не выдаются как новые контекстные ответы и не занимают новые ключи.
Ограничения неизменяемости и частичные уникальные индексы схемы 35 сохраняются.
Разные истории/области/состояния данных не разделяют один ответ. Проверяется на
настоящей PostgreSQL, включая роль `radar_kb_public`. Production-миграция не нужна.

## Границы

Это изменение контекста и области поиска, не замена конвейера извлечения знаний.
Необработанные статьи по-прежнему не становятся доступными диалогу автоматически.
Предел восемь цитат и существующая проверка ответа по свидетельствам сохраняются.
История не серверная учётная запись: она живёт в браузере, на другом устройстве
не появляется. Размер запроса ограничен 48 KiB до разбора JSON.
