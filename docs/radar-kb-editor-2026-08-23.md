# Срез 2.12: режим редактора — очередь, с которой можно работать

Дата: 2026-08-23. Состояние: **работает на Local Ru, только loopback**.

## 1. Как открыть

С вашей машины:

```bash
ssh -N -L 19702:127.0.0.1:19702 -i /root/.ssh/local_ru_admin root@147.45.99.225
```

И в браузере — адрес с токеном. Токен лежит на хосте в `/etc/radar-kx/editor.env`:

```bash
ssh -i /root/.ssh/local_ru_admin root@147.45.99.225 \
  'grep RADAR_KX_EDITOR_TOKEN /etc/radar-kx/editor.env | cut -d= -f2'
```

```
http://127.0.0.1:19702/?token=<токен>
```

## 2. Что видно

На каждое утверждение wiki — карточка: сам текст утверждения, его тип, страница, откуда оно, и под
ним предложенные цитаты. У каждой цитаты — текст, ссылка на источник, **точные смещения символов** и
релевантность. Две кнопки: подтвердить, отклонить.

Утверждения отсортированы так, что сначала идут те, у которых есть сильное предложение.

Сегодня в очереди: **312 утверждений, 2 769 предложений**.

## 3. Почему только loopback

ADR-0005 §16: у KX нет публичного доступа — ни порта, ни маршрута в Caddy, ни записи DNS. Сервис
читает полные тексты чужих материалов, поэтому это свойство юнита, а не намерение:
`IPAddressDeny=any`, `SocketBindAllow=ipv4:tcp:19702`, привязка к `127.0.0.1`. Проверено: снаружи
соединение отклоняется.

Вынести это на `radar.agpm.space/editor` (P21) — **отдельное решение с отдельным юнитом**, и оно в
списке того, что требует вашего слова.

## 4. Три свойства, которые дают не аккуратность, а устройство

1. **Токен проверяется на каждом запросе, включая саму страницу.** Страница — это и есть интерфейс
   редактора, а URL не является учётными данными (ADR-0006 §7). Сравнение постоянного времени.
   Токен короче 24 символов сервис отказывается принимать при запуске: короткий токен на сервисе,
   который читает чужие полные тексты, — не токен, а лежачий полицейский.
2. **Актор берётся из токена, никогда из тела запроса.** Сервис, который принимает имя в теле,
   записывает то, кем вызывающая сторона захотела побыть.
3. **Каждое решение — append-only событие с актором и scope** (ADR-0006 §3, §12). Миграция 016
   заводит одну таблицу `editorial_decisions` на все виды объектов: подтверждённая привязка,
   принятая идея, утверждённый алиас — это один и тот же вид факта, и одна таблица означает одно
   место, где читается история того, кто что решал.

## 5. Отказ — это решение, а не отсутствие

Раньше отклонить привязку было негде. Рецензент, который посмотрел и сказал «нет», оставлял тот же
след, что и тот, кто её не открывал, — и очередь предлагала её снова завтра. Теперь у
`concept_evidence` есть `rejected_at`/`rejected_by`, CHECK не даёт быть и подтверждённой, и
отклонённой, а вид `concept_evidence_queue` показывает только нерешённое.

## 6. Группировка по утверждению, а не по привязке

Решение, которое принимает рецензент, относится к **утверждению**: «что из этого, если хоть
что-нибудь, есть то, на чём стоит эта фраза». Плоский список из 2 769 предложений — это та же
информация, разложенная так, что по ней нельзя действовать.

## 7. Только стандартная библиотека

Инструмент разбора для одного человека не оправдывает веб-фреймворк в locked requirements, который
потом несёт каждый деплой воркера ради одной страницы. `http.server` + одна HTML-страница рядом с
модулем.

## 8. Эксплуатация

```bash
systemctl status radar-kx-editor
journalctl -u radar-kx-editor -f          # по строке на запрос, без токена
kxrun evidence-queue --limit 5            # то же самое в JSON
kxrun editorial-history                   # кто что решал
kxrun editor-token                        # сгенерировать новый
```
