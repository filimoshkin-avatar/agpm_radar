## Часть 1. Границы цитат

### Что оказалось не так, как записано

В документе достижимости стояло: **порвано границей 682 цитаты, 8,6 %**. Число
получено по форме самой цитаты — чем она кончается и с какой буквы начинается.

Если спрашивать не цитату, а **исходный текст вокруг неё**, картина другая.
Цитата, которая начинается с заглавной буквы, всё равно может начинаться в
середине предложения:

> «...By February 2026, **five of the six US military branches had formally
> adopted GenAI.mil**...»

Здесь в базе лежит только выделенное. Потеряны дата, охват и половина факта — но
по форме цитата выглядит целой, и в счёт 682 она не вошла.

Мера по исходному тексту: **4 773 цитаты из 13 876 (34,4 %) стоят хотя бы одной
границей не там**. Это не новый дефект, а тот же самый, посчитанный по тому, что
читателю видно.

### Что делает починка

Расширение границ на месте, по сохранённому полному тексту. Идентификаторы
сохраняются: на `claim_evidence` стоит единственный триггер, и он срабатывает
`BEFORE INSERT OR UPDATE`, то есть заново доказывает дословность расширенной
цитаты. Ничего не осиротеет.

Три правила не дают починке превратиться в переписывание:

1. **Двигается только порванная сторона.** Цитата, которая уже начинается после
   точки, с начала пункта списка или с края ячейки таблицы, с этой стороны не
   трогается. **9 103 цитаты (66 %) не меняются вообще.**
2. **Не дальше блока.** Заголовок — заголовок, пункт списка — пункт, ячейка —
   ячейка, для прозы потолок — абзац. Это и есть потолок из плана, и это же
   правило публикации `within_one_paragraph`: расширенная цитата не может выпасть
   из правила, внутри которого была.
3. **Только наружу.** Результат всегда содержит исходную цитату целиком.

### Два ограничителя, выведенных из замера, а не выбранных

- **Не больше 300 знаков на сторону.** Предложение в этом корпусе — 115 знаков по
  медиане, 229 по 90-му перцентилю, 281 по 95-му (замер по 47 782 предложениям).
  Если до точки дальше 300 знаков, пересекается не предложение, а склеенная
  таблица, исходник диаграммы или слайд из буллетов без пунктуации. Это второй
  дефект — следы разбора PDF, — и он чинится только перепарсингом.
- **Перевод строки пересекается, только если он перенос.** Половина корпуса —
  PDF с жёсткими переносами, где разрыв строки не значит ничего. Другая половина
  разрывов значит всё: таблица, разложенная в текст, — одна строка на строку.
  Признак: строка считается переносом, если она не короче четырёх пятых самой
  длинной строки своего блока. Правило самонастраивается — фиксированная ширина
  была бы неверна и для 60-колоночного PDF, и для источника без переносов вовсе.

### Что сдвинется следом

| | |
|---|---|
| **Эмбеддинги** | 4 773 вектора станут описывать текст, которого больше нет. `embed` теперь сам замечает это: он сверяет сохранённый `text_sha256` с текстом и переcчитывает разошедшиеся. Прогон — минуты (13 567 цитат за 11 минут на 4 ядрах). |
| **Опубликованные цитаты** | **2 170 из 6 664** опубликованных цитат указывают на спан, который расширяется. `published_quotes` неизменяема по решению P19 (это журнал того, что выпущено), и путь публикации отказывается публиковать одну и ту же цитату дважды. Значит после починки опубликованный срез и хранилище разойдутся на 2 170 цитат. |
| **Привязки к понятиям** | 333 из 1 129 |
| **Идеи** | 54 из 168 |
| **Карантин публикации** | 111 из 395 |

**Почему расхождение с опубликованным срезом сейчас не срочно.** Публичного
HTTP-доступа к KX нет вообще: наружу торчит только редактор владельца. Ни одна
из 6 664 опубликованных цитат сегодня не видна читателю. Разойдётся внутренний
снимок, а не сайт. Привести его в порядок нужно **до этапа 3**, и это отдельная
работа: колонка «заменена» плюс путь перепубликации, миграция на одну колонку.

Расчёт релиза при этом не ломается: `published_quotes` хранит свой собственный
текст и свои координаты, полный текст версии не меняется ни на знак, так что
каждая опубликованная строка остаётся дословной — просто более узкой, чем
доказательство в хранилище.

### Как посмотреть и как применить

```bash
kxrun repair-spans --examples 40      # сухой прогон, ничего не пишет
kxrun repair-spans --apply            # применить
kxembed embed --owner-kind claim_evidence   # пересчитать разошедшиеся векторы
```

## Часть 2. Даты публикации

### План занижал наличие дат втрое с лишним

В плане: «внутри периметра разбираемая дата есть только у ~185 материалов из
1 102». Замер: **8 025 документов из 8 354 (96 %) получают настоящую дату
публикации.** Внутри периметра выпусков сырые значения — ISO без единого
исключения.

| Точность | Документов |
|---|---:|
| день | 7 986 |
| месяц | 34 |
| год | 5 |
| ничего не разобрано | 329 |

Диапазон: **2021-06-15 … 2026-08-21**.

Не разобрано 18 значений вида «2 hours ago», «4 days ago» — и это сделано
намеренно. Пересчитать их относительно момента съёма можно, но результатом будет
дата публикации, которая на самом деле арифметика по обходу. Запасной путь и так
даёт этим материалам верный день и честно говорит, откуда он.

### Что видно на той части, где уже есть знание

Из 311 документов, к которым привязаны утверждения:

| | Документов | С датой публикации | С датой обнаружения |
|---|---:|---:|---:|
| периметр выпусков | 276 | **247** | 29 |
| канон AgPM | 35 | 0 | 35 |

Канон — методические документы, загруженные файлами; даты публикации у них в
хранилище нет ни в каком виде. Обсерватория покажет им дату загрузки с пометкой.

### Что добавляет миграция 023

Одна таблица `document_dates`, по строке на документ. Правило владельца записано
не намерением, а ограничениями:

- `shown_on` **NOT NULL** — у каждого документа есть день, потому что
  `document_versions.fetched_at` есть всегда;
- `shown_kind` — `published` или `first_seen`, и проверка не даёт поставить
  «published» там, где дата не разобрана;
- `date_precision` — месяц хранится как первое число, но так и назван месяцем;
  сортировка хроники — единственное, ради чего нужна эта форма;
- `published_raw` и `raw_source` — что было прочитано и откуда, чтобы неверную
  дату можно было проследить до текста, из которого она взялась.

Таблица — пересчёт, а не решение: повторный прогон с лучшим разбором оставляет
одну строку на документ, а не второе мнение рядом с первым.

```bash
kxrun resolve-dates          # сухой прогон
kxrun resolve-dates --apply  # после применения миграции 023
```

## Что вышло на самом деле

Применено 2026-08-23, окно ~40 минут. Порядок: остановлены таймеры ingest и
perimeter-poll → бэкап → выкат кода → починка границ → пересчёт векторов →
миграция 023 → выкат кода со `SCHEMA_VERSION = 23` → заполнение дат → таймеры
обратно.

Бэкап: `/var/lib/postgresql/backups/radar_kx-pre-stage0a-20260823T161950Z.dump`,
399 МБ, `pg_restore --list` читается — 630 записей оглавления.

| Шаг | Итог |
|---|---|
| Починка границ | **4 774 цитаты** (4 773 в первый проход, 1 во второй) |
| Проверка после записи | 13 876 из 13 876 воспроизводятся дословно, хеши сходятся, ни одна не длиннее 911 знаков при потолке 1 500 |
| Неподвижная точка | третий проход не находит ничего |
| Пересчёт векторов | 4 773 за **2 мин 10 с**; расхождений хеша не осталось ни одного |
| Миграция 023 | схема **23**, таблица и два индекса |
| Даты | **8 354 строки**: 8 025 по дате публикации, 329 по дате обнаружения |
| Дым | полнотекстовый поиск отвечает, редактор поднят, таймеры активны |

### Одна цитата догнала границу вторым проходом

Расширение сдвигает окно, в котором меряется блок, поэтому редкая цитата
доходит до границы на проход позже. На production такая нашлась одна из 13 876.
`repair-spans --apply` теперь сам повторяет проход, пока очередной не изменит
ничего, но не более трёх раз; production потребовал два.

### Побочный результат: у корпуса не 2,5 месяца, а 18

Документ достижимости считал охват по дате обнаружения радаром и записал
«периметр покрывает 2,5 месяца (06–08.2026)», а UC-07 — «динамика за 12 месяцев»
— объявил невозможным. По **дате публикации** те же 311 документов, к которым
привязаны утверждения, ложатся на 18 месяцев:

| Месяц | Документов | | Месяц | Документов |
|---|---:|---|---|---:|
| 2021-06 … 2025-08 | по 1–2 | | 2026-03 | 18 |
| 2025-09 … 2025-12 | по 3–4 | | 2026-04 | 34 |
| 2026-02 | 6 | | 2026-05 | 23 |
| | | | 2026-06 | 55 |
| | | | 2026-07 | 59 |
| | | | 2026-08 | 93 |

Осмысленная масса начинается с **2026-02**: это семь месяцев, а не два с
половиной. Двенадцати месяцев с достаточной плотностью по-прежнему нет — хвост
до 2025-09 держится на трёх-четырёх документах в месяц. Так что UC-07 не стал
достижимым, но прежняя формулировка «данных нет вообще» мерила не то.
